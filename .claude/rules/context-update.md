# Regla: Actualización de Contexto

## Cuándo actualizar docs/CONTEXTO.md
- Después de agregar una nueva funcionalidad
- Después de cambiar el stack o arquitectura
- Después de instalar una nueva herramienta o dependencia
- Después de resolver un bug significativo

## Cuándo actualizar docs/BITACORA.md
- Al inicio de cada sesión de trabajo (registrar qué se planea hacer)
- Al final de cada sesión (registrar qué se logró)
- Ante cualquier decisión técnica importante

## Cuándo actualizar docs/DECISIONES.md
- Cuando se elige una tecnología sobre otra
- Cuando se descarta un enfoque
- Cuando se cambia algo previamente decidido

## Cuándo actualizar docs/STACK.md
- Al agregar cualquier nueva librería, herramienta o servicio
- Al remover una dependencia

## Cuándo actualizar tasks/todo.md
- Al identificar nuevas tareas durante el trabajo
- Al completar una tarea (marcarla como hecha)
- Al re-priorizar

## Cuándo actualizar tasks/lessons.md
- Después de cada error o corrección del usuario
- Cuando se descubre un gotcha del proyecto
- Cuando un enfoque resulta mejor que otro

## Formato de entrada en BITACORA.md
```
### [YYYY-MM-DD] - Sesión N
**Objetivo:** qué se planea hacer
**Logros:** qué se logró
**Pendientes:** qué quedó para la próxima
**Notas:** observaciones relevantes
```
