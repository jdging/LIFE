Vista GastosFijos con acciones

Objetivo: crear una vista dedicada en AppSheet para la hoja GastosFijos con tres acciones: ver historial de un gasto, registrar un nuevo monto (sin borrar el anterior), y desactivar un gasto. Todo sin tocar código.

PARTE A — Crear la vista

Paso 1

Abrí AppSheet → tu app de Finanzas → menú lateral izquierdo → Views.

Paso 2

Clic en + New View. Configurá:

Paso 3 — Columnas visibles

Dentro de la vista, buscá la sección Column order. Mostrá solo las columnas útiles para el usuario. Sugerencia:

Paso 4 — Filtro: solo activos por defecto

En la vista, buscá Slice o Row filter condition y escribí:

[activo] = TRUE

Así la vista muestra solo los gastos activos. Los desactivados quedan en la Sheet como historial.

PARTE B — Acción 1: Actualizar monto

Esta acción no edita la fila existente. Agrega una fila nueva con el nuevo monto y una nueva fecha vigente_desde, preservando el historial. La lógica ya está en Apps Script (actualizarMontoFijo()), pero AppSheet no puede llamarla directamente. La solución es crear una nueva fila manualmente con el mismo ID de descripción.

Paso 5

En AppSheet → Behavior → Actions → + New Action.

Importante: Esta acción no borra la fila. Solo setea activo = FALSE. El gasto sigue en la Sheet como historial y no aparecerá en el dashboard porque el endpoint ?action=fixed filtra por activo = TRUE.

PARTE D — Acción 3: Agregar gasto nuevo

Paso 9

AppSheet agrega automáticamente el botón + para crear nuevas filas cuando la vista tiene el tipo Table con permisos de escritura. No necesita configuración extra.

Si querés un ícono personalizado o un label distinto: en la vista, buscá View Options → Add button y personalizá el label (sugerencia: + Agregar gasto fijo).

Paso 10 — Guardar y probar

Clic en Save en AppSheet. En el preview de la app, navegá a la vista "Gastos Fijos" y verificá:

— Las filas activas se ven correctamente.

— En cada fila aparece el botón/ícono "Nuevo monto" y "Desactivar".

— El botón + agrega una nueva fila en blanco.

Columna virtual Banco–Nombre en hoja Tarjetas

Objetivo: agregar una columna calculada en la hoja Tarjetas que combine banco y nombre de la tarjeta (ej: "Galicia – Visa"). Esta columna la usa AppSheet como label en el formulario de carga. El Log sigue guardando el ID (TC1, TD1, etc.) — nada existente se rompe.

Estructura actual de la hoja Tarjetas:
Col A: ID  ·  Col B: Nombre  ·  Col C: Tipo  ·  Col D: Banco  ·  Col E: Titular  ·  Col F: Día cierre  ·  Col G: Día vencimiento
Paso 1

Abrí la Google Sheet de Finanzas → pestaña Tarjetas.

Paso 2 — Agregar encabezado

Hacé clic en la celda H1 y escribí:

label

Este es el nombre de la columna nueva. En minúsculas para consistencia con el resto.

Paso 3 — Escribir la fórmula en H2

Hacé clic en la celda H2 y escribí la siguiente fórmula:

=D2&" – "&B2

Esto concatena Banco (col D) + " – " + Nombre (col B).
Resultado para una fila típica: Galicia – Visa o Santander – Mastercard.

Paso 4 — Copiar la fórmula hacia abajo

Con H2 seleccionada, copiá la celda (Ctrl+C) y pegala en H3, H4, H5… hasta cubrir todas las filas con tarjetas. O usá el truco del cuadrado azul: arrastrá desde la esquina inferior derecha de H2 hacia abajo.

Tip: Si las tarjetas que no tienen banco asignado muestran " – Visa", podés mejorar la fórmula para manejar ese caso: =IF(D2="", B2, D2&" – "&B2)
Paso 5 — Verificar el resultado

La columna H debería verse así (ejemplo):

A (ID)B (Nombre)D (Banco)H (label) ← nuevo
TC1VisaGaliciaGalicia – Visa
TC2MastercardSantanderSantander – Mastercard
TD1Visa DébitoGaliciaGalicia – Visa Débito
Paso 6 — Configurar en AppSheet (opcional pero recomendado)

Para que AppSheet use esta columna como display label al elegir tarjeta en el formulario:

AppSheet → Data → tabla Tarjetas → columna label → en la sección Column type verificá que sea Text y que esté marcada como Show? = sí.

Luego, en la tabla Log, columna tarjeta: buscá el campo Label column o Description dentro del tipo Ref. Seleccioná label como columna de display. Así en el formulario de carga el usuario ve "Galicia – Visa" en lugar de "TC1".

Sin impacto en datos: El valor que se guarda en el Log sigue siendo el ID (TC1). El label es solo visual en el formulario.

Columnas tipo_proporcion y proporcion_jd en hoja Log

Objetivo: agregar dos columnas nuevas al final de la hoja Log para habilitar la feature F-04 (proporción personalizada por gasto). La lógica del dashboard que las consume se implementa después — por ahora solo se agregan las columnas y su validación.

⚠ No re-ejecutar setupFinanzasSheet(). Eso borraría todos los datos existentes. Estas columnas se agregan manualmente a la sheet que ya está en producción.
Estructura actual del Log (16 columnas):
id · fecha · tipo · categoría · subcategoría · descripción · monto_total · cuotas_total · cuota_nro · cuota_ref · medio_pago · tarjeta · pagó · es_fijo · notas · borrado

Las dos columnas nuevas van en las posiciones Q (17) y R (18).

COLUMNA Q — tipo_proporcion

Paso 1 — Agregar encabezado

Hacé clic en la celda Q1 y escribí:

tipo_proporcion
Paso 2 — Aplicar validación de datos (dropdown)

Seleccioná el rango Q2:Q5000 (o hasta donde lleguen tus datos más un margen).

Menú Datos → Validación de datos → + Agregar regla. Configurá:

CampoValor
CriteriosEl menú desplegable (lista de ítems)
Valor 1dinamica
Valor 250/50
Valor 3custom
Mostrar advertencia / RechazarMostrar advertencia (no bloquear)
Por qué "Mostrar advertencia" y no "Rechazar entrada": Las filas nuevas creadas por el trigger de Apps Script (auto-ID, expansión de cuotas) no pasan la validación si está en modo estricto. Con advertencia, las filas se crean igual y el campo queda vacío — el dashboard interpreta vacío como "dinamica".
Paso 3 — Valor por defecto (opcional)

No es posible setear un valor por defecto en Google Sheets para filas nuevas a través de la validación. El valor por defecto "dinamica" lo maneja el dashboard (trata vacío como dinámico) y AppSheet (configurar default allá en el Paso siguiente).

COLUMNA R — proporcion_jd

Paso 4 — Agregar encabezado

Hacé clic en la celda R1 y escribí:

proporcion_jd
Paso 5 — Validación de datos (número entre 0 y 100)

Seleccioná el rango R2:R5000.

Menú Datos → Validación de datos → + Agregar regla:

CampoValor
CriteriosEl número es
Condiciónentre
Mínimo0
Máximo100
Mostrar advertencia / RechazarMostrar advertencia

Esta columna solo tiene sentido cuando tipo_proporcion = "custom". En todos los demás casos queda vacía y el dashboard la ignora.

FORMATO OPCIONAL

Paso 6 — Dar formato visual a los encabezados nuevos

Para que Q1 y R1 tengan el mismo estilo que los demás encabezados del Log:

1. Seleccioná P1 (la columna notas, última antes de las nuevas) → copiá el formato (Ctrl+Alt+C en Windows).

2. Seleccioná Q1:R1 → pegá el formato (Ctrl+Alt+V).

Así los dos encabezados nuevos quedan con el mismo fondo y color de texto que el resto.

Paso 7 — Congelar columnas (si está configurado)

Si el Log tiene columnas congeladas (para que el encabezado quede fijo al hacer scroll), verificá que las nuevas columnas Q y R queden fuera de la zona congelada. Menú Ver → Inmovilizar → Hasta la columna actual — revisá que no se hayan agregado accidentalmente a la zona fija.

CONFIGURACIÓN EN APPSHEET

Paso 8 — Sincronizar AppSheet con la Sheet actualizada

AppSheet detecta automáticamente columnas nuevas en la próxima sincronización. Para forzarla:

AppSheet → Data → tabla Log → clic en Regenerate structure (o el ícono de sincronización).

Las columnas tipo_proporcion y proporcion_jd deberían aparecer.

Paso 11 — Guardar y probar

Guardá en AppSheet. Cargá un gasto de prueba:

— Con tipo_proporcion = "dinamica": el campo % JD no debe aparecer.

— Con tipo_proporcion = "custom": el campo % JD debe aparecer y aceptar un número entre 0 y 100.

— Verificá en la Sheet que la fila tenga los valores correctos en las columnas Q y R.
